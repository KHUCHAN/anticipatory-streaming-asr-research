**A model that further reflected the core learning principles of the original text was implemented and learned, but did not outperform the existing method in this single token display condition. The main benefit is to make the predictor's holding context a fixed size. This is not to say that FGN as a whole is impossible for ASR.**

6 models were trained respectively, 16epoch gates were calibrated with dev2711 models, and all test5559 models were evaluated. The 12 results of the existing native/full/band2 control group were accurately reproduced. The new main model advanced clean85.02ms/other72.17ms. The existing band2 was 89.58/70.28ms, and the full AR was 94.31/75.31ms. The difference compared to band2 is clean−4.57ms (95%CI−5.78~−3.38) and other+1.89ms (+0.66~+3.10). Actual test false forecasts increased from band2 to 0.375/0.537 to the new model 0.416/0.578 (per 100 native BPE token). Therefore, we do not claim accuracy-delay superiority or new Pareto improvements. The curves of 5 points predetermined with various dev risk budgets were also saved.

**If you prioritize current delay and computation performance, it is better to maintain the existing full/band2+gate. If strict state constraints are the goal, the new continuous-state predictor is an alternative, of which the noise-free model is lighter. There is insufficient evidence to significantly increase the stochastic FGN model based on these results alone.**

The FGN elements can be divided and read as follows.

- **The learned continuity state prediction is valid.** The persistence control group without learning, which repeated the last voice chunk as is, advanced only about 1.1ms. The new model's 85/72ms cannot be explained simply by the effect of rereading a voice that has already been seen. However, surpassing the previously learned AR predictor is another thing, and it was not surpassed here.
- **The visible benefit of the additional persistent memory was not confirmed.** Even when the memory was reset to the last two encoder states, it was clean85.34/other71.67ms. The difference from the main model is +0.32/−0.50ms, and both splits include 95%CI and 0. This is not proof of equivalence that the effect is exactly 0. Also, since the latest encoder state itself already contains the past context of the default Zipformer, this does not mean that all past information is unnecessary.
- **Noise improves the probability prediction score, but the display gain is approximately the same.** The marginal CRPS of the separate path diagnosis was the noise model0.547, and the deterministic model0.771. However, the displayed gain of the critical model was 84.96/71.68ms, and the difference from the main model was only 0.06/0.49ms, and the difference 95%CI included 0. The additional CPU cost is approximately 2.93ms/chunk to 7.05ms/chunk. An improved probability score does not equate to an improvement in subtitle delay.
- **Multi-step backpropagation is helpful in predicting future features.** The fixed H4 verification token NLL of the selected checkpoint was multi-step2.05, one-step learning3.41. However, the indicated gain of one-step learning was 85.52/72.36ms, which was not statistically distinguishable from the main model. The value of applications that show multiple tokens simultaneously on the actual screen cannot be denied with this single token policy.
- **The stand-alone model ensemble had no gain on the current display target.** The display gain was about 84.26/71.36ms, which was about 0.8ms lower than the main model, and the additional CPU cost was about 9.5ms/chunk. The false forecast was slightly lower, but did not show superiority in overall risk and delay.
- **The ASR token auxiliary loss was useful.** The CRPS-only model that removed it had lower continuous-state CRPS, but with a reduced indicative gain of 81.41/69.98ms. Compared to the main model, −3.61/−2.19ms and 95%CI all increased by +0.051/+0.056, except for 0. The model that removed the token auxiliary loss also selected only CRPS as the checkpoint, but in this comparison, 16epoch was selected for both the main model and CRPS-only. This result shows that word-level usefulness is not guaranteed just by matching the marginal distribution of arbitrary ASR hidden features well.
- **Useful temporal joint structure was not established.** Of 256 model-selection utterances, 250 qualified for a 4-step, 16-path diagnostic. Joint energy was 0.70382 for coherent paths and 0.69565 after independently shuffling members per frame (lower is better). The coherent-minus-shuffled difference was +0.00817, with 95% CI +0.00789~+0.00845. Marginals and marginal CRPS are exactly preserved, so temporal coupling was not beneficial in this diagnostic. Two-token hit@16 remained 64.8%; three-token hit changed from 38.96 to 39.76%. This uses the checkpoint-selection development set, not an independent test or reference-word accuracy evaluation.
- **The maintenance context has been greatly reduced and the actual storage space has also been confirmed.** In the two test splits, the context peak of the existing band2 is 7077.86KiB (text+audio KV), and the new main model is 33KiB, which is about 214 times the difference. The full AR is 9233.41KiB. We also checked that the actual tensor storage of the new model remained 33KiB for 10 minutes worth of observations. This is a figure excluding weight, temporary activation, prediction branch, backbone, and offline cache, and does not claim that the total RAM has been reduced by 214 times. The computational cost of the new model is actually higher.

The surviving direction is **predicting future features with small continuous state, checking with actual audio/native decoding, and supporting display with bounded predictor state**. Shared noise, extra persistent memory and ensembles did not add useful single-token display benefit here; multi-step learning helped continuous-state scores. Scope: one strong pretrained Zipformer, 100h added training, approximately 6.3M predictors, two primary seeds and one-seed component controls. This does not reject original 180M weather FGN or all other ASR representations/multi-token applications.
